## 1. ГЛАВНАЯ ЦЕЛЬ

Trader_7_12 Pro — утренний аналитический scanner/assistant для самостоятельной интрадей-торговли **фьючерсами Московской биржи**.

Главная задача не состоит в том, чтобы показать пользователю весь рынок. Задача — быстро найти **2–3 наиболее интересных ликвидных и активных базовых актива**, в которых сегодня есть деньги, объём, движение и понятная сила/слабость, а затем показать соответствующий фьючерс, которым пользователь уже торгует самостоятельно.

Канонический принцип:

> **Сканер находит ГДЕ смотреть. Пользователь решает ГДЕ и КОГДА входить.**

Приложение не исполняет сделки и не заменяет решение пользователя.

---

## 2. ЧТО ИЩЕМ КАЖДОЕ УТРО

Сканер ищет не «самые дорогие» и не просто «самые ликвидные» инструменты.

Нужен актив, где одновременно присутствуют:

1. **деньги / price × volume**;
2. **необычная текущая активность** относительно собственной нормы;
3. **объём**, достаточный для нормального движения и исполнения соответствующего фьючерса;
4. **волатильность / амплитуда движения**, достаточная для интересной внутридневной идеи;
5. **направление и дневный контекст**;
6. **относительная сила или слабость** относительно рынка;
7. **структура SPOT** и желательно первый pullback/rebound либо breakout;
8. **подтверждение фьючерсом**;
9. разумный потенциал дальнейшего движения.

Если качественных кандидатов только один или два — сканер **не обязан искусственно заполнять TOP-3**.

## 3. UNIVERSE — ЧТО СКАНИРУЕМ

Кандидаты формируются из двух источников.

### 3.1. Акции IMOEX

Для акций используется **текущий состав индекса Московской биржи IMOEX**, загружаемый динамически через MOEX ISS.

На 19.08.2026 live-проверка показала:

- IMOEX constituents: **46**;
- с доступным futures mapping: **43**;
- без доступного futures mapping: **3**.

Пример бумаг без текущего futures mapping: `CNRU`, `MSNG`, `UGLD`.

Текущий IMOEX universe не должен быть зашит вручную: состав должен обновляться из MOEX ISS.

`IRUS/IRUS2` — рыночные обозначения/benchmark, а не отдельный список акций.

### 3.2. Отдельные рыночные активы

Кроме IMOEX-акций сканер должен контролировать основные самостоятельные центры движения:

- **нефть**;
- **золото**;
- **газ**;
- **USDRUB**.

Для них также применяется SPOT-first логика и затем выбирается соответствующий фьючерс.

Таким образом, единый поиск выглядит так:

`IMOEX stocks + OIL + GOLD + GAS + USDRUB`

После анализа всех групп они **конкурируют между собой за общий TOP 2–3**.

Нельзя заранее резервировать одно место под акцию, одно под нефть и одно под валюту. Если сегодня рынок даёт три сильных акции — TOP может состоять из трёх акций. Если лучшие возможности — нефть, золото и USDRUB — именно они должны попасть в TOP.

## 4. SPOT-FIRST АРХИТЕКТУРА

Жёсткое правило проекта:

`SPOT → SPOT STRUCTURE → STRENGTH/WEAKNESS → FUTURES CONFIRMATION → USER ENTRY`

SPOT является источником:

- направления;
- рыночной структуры;
- money/activity;
- волатильности;
- силы/слабости;
- setup.

Фьючерс является **торговым инструментом пользователя** и дополнительным подтверждением.

Pullback/rebound и структурные уровни измеряются на SPOT, а не на графике фьючерса.

---

## 5. MARKET BENCHMARK — IMOEX2 / IRUS2

Главный benchmark российского рынка — **IMOEX2 / IRUS2**.

Он нужен прежде всего для определения общего состояния рынка и Relative Strength.

### Сильный актив

Для LONG предпочтителен актив, который:

- растёт быстрее рынка при росте рынка;
- падает медленнее рынка при снижении рынка;
- сохраняет относительное превосходство после отката.

### Слабый актив

Для SHORT предпочтителен актив, который:

- падает быстрее рынка при снижении рынка;
- растёт хуже рынка при росте рынка;
- сохраняет относительную слабость после отскока.

RS должен быть **реально рассчитан**, а не подставлен искусственно.

Если benchmark или необходимые данные недоступны, выводится `RS_UNAVAILABLE`, а RS не должен получать фиктивное значение.

---

## 6. MONEY — ГДЕ ДЕНЬГИ

Каноническая базовая метрика:

`money_volume = price × volume`

Учитываются одновременно:

- текущий SPOT money volume;
- средний completed-day SPOT money volume;
- текущий session money volume;
- money volume в единицу времени;
- текущая активность относительно ожидаемой активности;
- futures money volume и trades — для проверки практической торгуемости фьючерса.

Главный вопрос:

> **Насколько сегодняшний поток денег необычен для этого конкретного актива?**

Поэтому абсолютный оборот сам по себе недостаточен. SBER с огромным оборотом не должен автоматически обгонять менее крупный актив, если у второго сегодня намного сильнее аномалия активности и движение.

Ключевой показатель активности:

`activity_ratio = current_session_money / expected_money_to_now`

где ожидаемый money рассчитывается относительно завершённого дневного среднего и уже прошедшего времени текущей сессии.

---

## 7. ОБЪЁМЫ

Объём используется в двух смыслах:

1. **ликвидность** — достаточно ли реального объёма для торговли;
2. **подтверждение движения** — поддерживает ли объём текущее движение.

Приоритет получают активы, где одновременно наблюдаются:

- высокий money volume;
- повышенный объём;
- ускорение activity;
- движение цены в согласованном направлении.

Рост цены без объёма не должен автоматически считаться сильным сигналом.

---

## 8. ВОЛАТИЛЬНОСТЬ И ПОТЕНЦИАЛ

Волатильность — обязательный фактор отбора.

Сканер должен учитывать, насколько текущая амплитуда движения актива велика относительно его собственной нормальной амплитуды.

Нас интересует не максимальная волатильность сама по себе, а **полезная волатильность**:

- движение достаточно велико, чтобы иметь внутридневной потенциал;
- движение не является полностью хаотичным;
- есть ликвидность;
- есть структура;
- направление согласуется с силой/слабостью;
- есть место для продолжения движения.

Потенциал должен оцениваться относительно текущей цены, структуры и исторической/обычной амплитуды, а не только по одному проценту изменения.

---

## 9. ДНЕВНЫЙ ТРЕНД

Daily timeframe — базовый контекст.

Предпочтительно видеть 2–3 последовательных дня движения в одном направлении, но отсутствие такой серии не является автоматическим запретом, если intraday движение и другие факторы очень сильны.

Рабочие состояния:

- `UPTREND`;
- `WEAK_UPTREND`;
- `DOWNTREND`;
- `WEAK_DOWNTREND`.

Daily trend нужен для отделения устойчивого движения от случайного шума.

---

## 10. SPOT STRUCTURE / SETUP

Основной структурный контекст — H1 SPOT.

Session formation — M5 SPOT.

### LONG

`H1 context → impulse up → first pullback → consolidation/stabilization → strength remains → futures confirmation`

### SHORT

`H1 context → impulse down → first rebound → consolidation/stabilization → weakness remains → futures confirmation`

Ориентир retracement — около **50% импульса**. Рабочая зона может быть шире, примерно 35–75%, если структура остаётся качественной.

Состояния:

- `WAIT` — usable setup ещё нет;
- `WATCH` — формируется pullback/rebound и стабилизация;
- `CONFIRMED` — структура получила последующее подтверждение.

Setup является фактором качества кандидата, **не автоматической точкой входа**.

---

## 11. СИЛА / СЛАБОСТЬ ДОЛЖНА СОГЛАСОВЫВАТЬСЯ С НАПРАВЛЕНИЕМ

Для итогового ranking важно не просто наличие RS, а его согласованность:

- `LONG + STRONGER` — сильная комбинация;
- `SHORT + WEAKER` — сильная комбинация;
- `LONG + WEAKER` — штраф;
- `SHORT + STRONGER` — штраф.

Особенно важно отслеживать **сохранение силы/слабости после pullback/rebound**.

---

## 12. «ВЕРОЯТНОСТЬ» / CONFIDENCE

Понятие «вероятность» в проекте означает **оценку уверенности системы в качестве текущего сценария**, а не математически доказанную вероятность прибыли.

До отдельной исторической калибровки нельзя показывать пользователю псевдоточность вроде `78.4% chance of profit`.

Используется объяснимый `confidence_score`, который собирается из:

- direction/trend;
- relative strength/weakness;
- money/activity;
- volume;
- volatility/potential;
- setup quality;
- futures confirmation;
- data quality.

В будущем confidence может быть откалиброван на historical replay и тогда отображаться как статистически обоснованная вероятность только при наличии достаточной выборки.

---

## 13. ИТОГОВЫЙ RANKING

Итоговый рейтинг должен отвечать вопросу:

> **Где сегодня одновременно есть деньги, активность, движение, сила/слабость и качественный setup?**

Приоритет факторов:

1. **Current money/activity** — где сегодня реально появились деньги;
2. **Strength/weakness** относительно benchmark или релевантного рынка;
3. **Volume/liquidity**;
4. **Volatility/potential**;
5. **Direction/daily trend**;
6. **SPOT setup quality**;
7. **Futures confirmation/liquidity**;
8. **Data quality / freshness**.

Это не обязано быть жёсткой арифметической формулой на каждом этапе, но финальный score должен быть объяснимым и воспроизводимым.

Фьючерс с большим абсолютным оборотом не должен вытеснять SPOT-лидера с лучшим сочетанием активности, силы и потенциала.

## 14. ДВУХФАЗНЫЙ PIPELINE

Чтобы не тратить время на глубокий анализ всего universe:

### Phase 1 — FAST SCREEN

Для всех доступных кандидатов используются дешёвые признаки:

- daily trend;
- average money;
- current price change/momentum;
- preliminary activity/liquidity;
- preliminary radar score.

### Phase 2 — DEEP ANALYSIS

Только лучшие предварительные кандидаты получают дорогой анализ:

- RS;
- H1 structure;
- M5 pullback/rebound;
- volatility/potential;
- setup quality;
- detailed session money;
- futures confirmation.

После этого все группы объединяются и выбираются **TOP 2–3**.

Целевой normal live scan: **20–30 секунд**.

Сетевые запросы должны быть fail-fast, повторные запросы ограничены, metadata кэшируется, независимые запросы допускают bounded concurrency.

Временный сетевой сбой не должен превращаться в ложное `NO CANDIDATES`.

## 15. FUTURES → SPOT MAPPING

Mapping должен быть динамическим и опираться на BCS underlying metadata.

Приоритет:

1. явное underlying security code;
2. явный underlying ticker + class code;
3. однозначный metadata fallback;
4. неоднозначное соответствие — **REJECT**, без угадывания.

Канонический regression:

`BMU6 → BRENT1026`

Фьючерсы с истёкшим сроком или с критически близким expiry не используются. При нескольких допустимых сроках для одного SPOT выбирается один практически торгуемый контракт.

## 19. ЧТО ПОЛЬЗОВАТЕЛЬ ДЕЛАЕТ САМ

Пользователь самостоятельно:

- смотрит график;
- выбирает точку входа;

## 20. ЧТО ЗАПРЕЩЕНО В ПРОЕКТЕ

Не добавлять в scanner pipeline:

- автоматическое исполнение ордеров;
- автоматическую команду BUY/SELL;
- автоматическую точку входа;
- position sizing;
- управление депозитом;
- автоматический SL/TP;
- portfolio management;
- автоматическое управление открытой позицией.

Historical replay остаётся **READ ONLY — NO ORDERS**.

## 22. ДАННЫЕ И НАДЁЖНОСТЬ

Если обязательная рыночная зависимость недоступна, кандидат не должен превращаться в ложный нулевой score.

Система должна различать:

- `NO_CANDIDATE` — данные есть, подходящего кандидата нет;
- `DATA_INCOMPLETE` — обязательные данные отсутствуют;
- `TRANSIENT_ERROR` — временная ошибка сети/API.

Кэш и bounded retry допустимы, но не должны скрывать проблему с данными.
