## 1. ЦЕЛЬ ПРОЕКТА

Trader_7_12 Pro — аналитический scanner/assistant для самостоятельной торговли **фьючерсами Московской биржи**.

Пользователь торгует только фьючерсами. Идея и направление определяются по **SPOT / базовому активу**, а соответствующий фьючерс является практическим инструментом сделки.

Главный вопрос сканера:

> **В каком SPOT сегодня есть деньги, активность, понятное направление и качественная структура, чтобы соответствующий фьючерс был интересен для самостоятельного поиска точки входа?**

Каноническая цепочка:

`SPOT → SPOT STRUCTURE → FUTURES CONFIRMATION → USER ENTRY`

**Сканер находит ГДЕ смотреть. Пользователь решает ГДЕ входить.**

---

## 2. ЧТО ДОЛЖЕН СКАНИРОВАТЬ СКАНЕР

Сканируется не небольшой ручной список, а весь доступный через BCS/MOEX релевантный universe.

Целевые группы:

- **акции MOEX** — все доступные и пригодные для анализа ликвидные акции, а не только SBER/LKOH/ROSN/TATN/PLZL/SNGSP/YDEX;
- **нефть**;
- **золото**;
- **газ**;
- **валюты** — прежде всего USD/RUB и CNY/RUB, плюс другие доступные релевантные валютные базовые активы.

Тикеры и class code должны определяться динамически по BCS metadata и mapping. Постоянный ручной universe запрещён.

Для каждого подходящего SPOT:

`CURRENT SPOT ACTIVITY / MONEY`
→ `DAILY DIRECTION`
→ `2–3+ DAY TREND`
→ `SPOT H1 STRUCTURE`
→ `FIRST PULLBACK / FIRST REBOUND`
→ `CONSOLIDATION / STABILIZATION`
→ `RELATIVE STRENGTH / WEAKNESS`
→ `CORRESPONDING FUTURES`
→ `FUTURES LIQUIDITY / CONFIRMATION`
→ `FINAL RANKING`

Фьючерс с большим оборотом не должен вытеснять более качественного SPOT-лидера.

## 3. КРИТЕРИИ ЛУЧШЕГО ИНСТРУМЕНТА

Приоритет факторов:

1. **Сегодняшняя активность и money volume SPOT.**
2. Достаточная текущая ликвидность.
3. Понятное направление движения.
4. Желательно последовательное направление **2–3 дня и более**.
5. SPOT impulse и H1/M5 структура.
6. Первый pullback для LONG / первый rebound для SHORT.
7. Консолидация и сохранение силы/слабости.
8. Relative Strength / Weakness относительно рыночного benchmark.
9. Ликвидность и подтверждение соответствующего фьючерса.
10. Итоговый ranking.

Ключевой показатель денег:

`money_volume = price × volume`

Для текущего дня приоритет имеет **текущий session SPOT money/activity**, а средний дневной оборот используется как контекст.

---

## 4. LONG / SHORT

### LONG

`SPOT impulse UP → first pullback DOWN → 35–75% retracement zone (50% preferred) → consolidation → strength remains → FUTURES confirmation`

### SHORT

`SPOT impulse DOWN → first rebound UP → 35–75% retracement zone (50% preferred) → consolidation → weakness remains → FUTURES confirmation`

Это фильтр качества и контекст для наблюдения, **не автоматическая точка входа**.

Итоговая выдача должна сохранять конкуренцию обеих сторон рынка:

- **TOP LONG** — лучшие текущие кандидаты на рост;
- **TOP SHORT** — лучшие текущие кандидаты на снижение.

Если качественных кандидатов меньше, чем 2–3, система честно показывает меньше. Заполнять список слабыми инструментами нельзя.

---

## 5. DAILY TREND

Daily timeframe — базовый фильтр направления.

Предпочтительно:

- 2–3 последовательных дня движения и более;
- устойчивый `UPTREND` для LONG;
- устойчивый `DOWNTREND` для SHORT.

Текущий незавершённый день не используется для исторического daily trend и среднего дневного оборота.

---

## 6. RELATIVE STRENGTH / WEAKNESS

Benchmark определяется динамически через BCS; каноническая идея проекта — **IMOEX2 / IRUS2**.

Сильный инструмент:

- рынок растёт → растёт сильнее рынка;
- рынок падает → падает слабее рынка / сохраняет устойчивость.

Слабый инструмент:

- рынок падает → падает сильнее рынка;
- рынок растёт → растёт хуже рынка / сохраняет слабость.

Если корректный benchmark или данные RS недоступны, система должна показывать `RS unavailable`, а не подставлять искусственное значение.

---

## 7. FUTURES → SPOT MAPPING

Основной сервис:

`Program/services/futures_spot_mapping_service.py`

Mapping только динамический и основан на BCS metadata.

Приоритет:

1. явный underlying security code / `baseAssetSecuritySecCode` или эквивалент;
2. явный underlying ticker/security object с class code;
3. однозначное совпадение SPOT metadata, если явного underlying нет;
4. неоднозначный или неразрешённый mapping отбрасывается.

Угадывать SPOT по названию запрещено.

Канонический regression:

`BMU6 → BRENT1026`

## 8. ВЫБОР ФЬЮЧЕРСА

После определения SPOT-лидера выбирается соответствующий актуальный фьючерс.

Правила:

- просроченные контракты исключаются;
- контракты с 3 и менее календарными днями до экспирации исключаются;
- если одному SPOT соответствуют несколько экспираций, остаётся один пригодный ликвидный контракт;
- futures money/trades/move используются для подтверждения и выбора практического контракта;
- высокий futures turnover не отменяет более сильную SPOT-идею.

## 9. ВРЕМЯ И СЕССИИ

Все торговое время проекта — `Europe/Moscow`.

- `06:50–07:00` PRE_OPEN;
- `07:00–10:00` MORNING — главное торговое окно;
- `10:00–19:00` MAIN;
- `19:00–23:50` EVENING;
- `23:50–06:50` CLOSED.

UI показывает живые дату, время МСК и текущую сессию. Countdown не нужен.

## 10. UI

Согласованный интерфейс:

- профессиональный спокойный тёмный дизайн;
- компактная верхняя часть;
- одна кнопка сканирования;
- во время сканирования кнопка мягко пульсирует зелёно-салатовым;
- большая область результатов во время сканирования показывает оригинальную сюрреалистическую анимацию с плавящимися часами;
- после сканирования анимация полностью исчезает;
- LONG — мягкий зелёный;
- SHORT — мягкий красный;
- двойных строк «идёт сканирование» нет;
- верхние поля не заменяются анимацией.

`QPainter` импортируется из `PySide6.QtGui`.

## 11. ПРОИЗВОДИТЕЛЬНОСТЬ

Целевой обычный live scan: примерно **20–30 секунд**.

Текущая архитектура оптимизации:

- динамический SPOT metadata cache;
- ограниченная параллельность независимых metadata запросов;
- ограниченная параллельность preliminary radar;
- fail-fast / bounded retry для BCS;
- двухфазный radar: дешёвый preliminary SPOT screen → глубокий H1/RS/M5 анализ только финалистов;
- deep shortlist должен сохранять конкуренцию LONG и SHORT.

Производительность нельзя улучшать ценой возврата к ручному universe или futures-first ranking.

## 14. ГЛАВНАЯ ТЕКУЩАЯ ЗАДАЧА

**УБРАТЬ LEGACY MANUAL SPOT UNIVERSE НАВСЕГДА.**

Нельзя оставлять `DEFAULT_INSTRUMENTS` и любые эквивалентные ручные списки как fallback для live scanner.

Live pipeline обязан строить universe динамически и рассматривать весь доступный релевантный рынок:

**акции + нефть + золото + газ + валюты.**

Затем он должен определить лучшие **LONG и SHORT**, а не выдавать только одного случайного кандидата.

---

## 15. ЧТО НЕ ДОБАВЛЯТЬ

Категорически не добавлять в scanner:

- автоматическое исполнение ордеров;
- автоматическую точку входа;
- position sizing;
- автоматический SL/TP;
- portfolio management;
- risk management как часть scanner pipeline;
- автоматическое управление сделкой.

Пользователь сам смотрит график, выбирает точку входа, размер позиции, риск и исполнение.

Historical replay — **read only**.
